iterates sources, parses Markdown once per source, groups PDF work by

`empty_sources`, `unknown_source`, `unused_source`, `conflicting_source_form`,

## Decisions made

All decisions from the previous handoff remain in force. New decisions:

- **Value-level desugaring for both evidence and config.** Serde's
  `#[serde(default)]` fills in default values for missing fields, making it
  impossible to distinguish "user omitted `markdown`" from "user set
  `markdown` to its default" at the struct level. Desugaring inspects the raw
  Value before defaults apply, so conflict detection is reliable. Config
  loading changed from `loader.load::<Config>()` to
  `loader.load::<serde_json::Value>()`, desugar, then `from_value::<Config>()`.
- **`BTreeMap` for sources, not `HashMap`.** Deterministic iteration order for
  error messages, JSON output, and test assertions.
- **`OcrEngine` trait extended, not replaced.** `ocr_page` stays generic over
  `&impl OcrEngine` because `tests/tesseract_cache.rs` calls it with mock
  trait objects. Config getters (`lang()`, `dpi()`, `psm()`) live on the trait.
- **`--format auto` is the new default.** JSON when piped, text on a TTY.
  Tests pass `--format text` explicitly.
- **Old `--json` still works.** librebar 0.6.0 accepts it as a hidden
  compatibility flag that resolves to `--format json`.

## What's next

The spec (`record/superpowers/specs/2026-07-30-multi-source-and-support-design.md`)
defines three remaining phases:

1. **Phase 2: Material tokens and section paths.** Required-token coverage
   checking (numbers, number words, quoted phrases), advisory tokens
   (capitalized multiword terms), section path recording/verification,
   `sections.weak` rules. Three new error codes: `uncovered_token`,
   `stale_section`, `weak_section_only`. Depends on Phase 1 (shares the
   per-source Markdown parsing).

2. **Phase 3: `propose`.** Deterministic candidate locator ranking. Depends
   on Phases 1 and 2 (shares the material-token extractor — defining it twice
   would let the proposer and validator disagree). No model, no randomness.

3. **Phase 4: Review tier.** Records a semantic verdict and binds it to both
   the claim text and the evidence set via dual SHA-256. Never produces a
   review, never treats verdict as truth. `--require-review` makes it a gate.

4. **Phase 5: Arbitrary OCR backends (deferrable).** `PdfBackend` becomes a
   validated name rather than a closed enum. Config-declared command templates.
   Independent of Phases 1–4.

## Landmines

- **`pdf.ocr` config is now honored** (was decorative). Setting `dpi: 600`
  actually renders at 600 DPI, and `enabled: false` actually prevents OCR.
  Phase 0 fixed this — it is no longer a landmine but worth noting because
  the change is cache-invalidating (new profile name format).

- **Config loading goes through `serde_json::Value` now.** Error messages for
  malformed config are slightly different from the old `load::<Config>()` path
  — they come from `serde_json::from_value` rather than librebar's
  `serde_path_to_error` wrapper. Acceptable for a pre-release tool.

- **`Corpus::markdown_candidates()` and `pdf_path()` delegate to `"default"`.** 
  They still work for all existing call sites, but new code should use the
  `_for(id, source)` variants. The delegates exist for backward compatibility,
  not as the preferred API.

- **`LocateResult` includes a `source` field now.** Any downstream consumer
  of `--json` output from `locate` will see a new top-level `"source"` key.
  Not a breaking change (JSON output was already subject to field additions),
  but worth knowing.

- **Test fixtures encode specific behavior, not sample data.**
  `mutool-rotated-table.json` must stay fragmented so native extraction
  cannot produce `42.8% within tolerance`; that absence is what forces the
  OCR path. The TSV geometry produces an asserted bounding-box width of 274.
  Changing either breaks a test for the wrong reason.

- **Phase 3 must follow Phase 2.** Both consume one material-token extractor.
  Defining it twice would let the proposer and the validator disagree about
  what a claim asserts, which is the worst possible place for a discrepancy.
